================================================================================
BEFORE vs AFTER BEHAVIOR
================================================================================

BEFORE (Sequential/Blocking):
  Request A (2s) ──→ Response A
  Request B (2s) ──→ WAIT WAIT WAIT ──→ Response B (Total: 4s)
  Request C (2s) ──→ WAIT WAIT WAIT ──→ WAIT WAIT WAIT ──→ Response C (Total: 6s)

AFTER (Concurrent/Async):
  Request A (2s) ──→ Response A
  Request B (2s) ──→ Response B (started immediately, completes same time)
  Request C (2s) ──→ Response C (started immediately, completes same time)
  Total: ~2s instead of 6s

================================================================================
THREAD POOL BEHAVIOR
================================================================================

Python's asyncio.to_thread() automatically:
  - Uses ThreadPoolExecutor (default: min(32, os.cpu_count() + 4) threads)
  - Queues blocking operations safely
  - Returns to event loop immediately
  - Completes blocking work in background
  - Delivers result back to async context

Result: Event loop NEVER blocks, handles 1000+ concurrent requests easily
