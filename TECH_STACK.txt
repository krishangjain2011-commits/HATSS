PROJECT OVERVIEW
================================================================================
HATSS is a comprehensive home security system that combines AI-powered facial
recognition with real-time sensor monitoring. The system includes a FastAPI
backend with asynchronous processing, a modern React frontend with real-time
updates, and ESP32 microcontroller integration for hardware sensor monitoring.

HARDWARE & IOT STACK
================================================================================

MICROCONTROLLER
  • ESP32 (DevKit v1)
    - Dual-core processor @ 240MHz
    - WiFi & Bluetooth connectivity
    - 32-bit ARM processor
    - 520KB RAM, 4MB Flash

PROGRAMMING ENVIRONMENT
  • Arduino IDE 2.x
    - IDE for uploading sketches to ESP32
    - Serial monitor for debugging
    - Library management

  • Arduino Core for ESP32
    - Open-source project to support ESP32 in Arduino IDE
    - Hardware abstraction layer

LIBRARIES (C++)
  • WiFi.h (Built-in)
    - WiFi connectivity (Station and AP modes)
    - Simultaneous AP + Station support

  • WebServer.h (Built-in)
    - HTTP server implementation
    - Handles GET/POST requests
    - CORS header support

  • HTTPClient.h (Built-in)
    - HTTP client for requests to backend

  • Wire.h (Built-in)
    - I2C protocol support
    - OLED display communication

  • Adafruit_GFX 1.x
    - Graphics library for OLED display
    - Text rendering, shapes, animations

  • Adafruit_SSD1306 1.x
    - OLED display driver (128x64)
    - I2C communication

SENSORS & HARDWARE
  • IR Motion Sensor (HC-SR501)
    - GPIO 27 (D27)
    - Active LOW logic (reversed)
    - Detects human motion/intrusion

  • Flame Sensor (typically photo-transistor based)
    - GPIO 32 (D32)
    - Active LOW logic
    - Detects fire/flame

  • MQ2 Gas Sensor (MQ Series)
    - GPIO 33 (D33) - Analog input (AO)
    - Detects combustible gases, smoke, LPG
    - Analog threshold: 2200
    - Rating scale: 1-10

  • Soil Moisture/Water Level Sensor
    - GPIO 34 (D34) - Analog input (A0)
    - Measures water level percentage (0-100%)
    - Raw analog range: 3500 (empty) to 1200 (full)

  • Active/Passive Buzzer
    - GPIO 25 (D25) - PWM output
    - LEDC Dual-Tone Alarm Siren
    - Frequencies: 2500Hz and 1800Hz (alternating)

  • 0.96" OLED Display (SSD1306)
    - 128x64 pixel display
    - I2C Protocol (default address: 0x3C or 0x3D)
    - SDA: GPIO 21 (D21)
    - SCL: GPIO 22 (D22)
    - Shows real-time sensor status and alerts

FIRMWARE FEATURES
  • Dual WiFi Mode
    - Access Point (AP): Creates HATSS_SECURITY_NET hotspot (192.168.4.1)
    - Station Mode: Connects to home WiFi and backend
    - Simultaneous operation possible

  • Real-time Sensor Polling
    - Digital input sampling (IR, Flame)
    - Analog input reading (MQ2, Water Level)
    - Debouncing (5 samples for stability)

  • OLED Display
    - Real-time sensor status visualization
    - Threat alerts with visual warnings
    - Water level beaker animation
    - Gas rating display

  • Buzzer Alarm
    - Dual-tone siren (alternating frequencies)
    - Mute control via API
    - Test functionality
    - Automatic activation on threat detection

  • Web Control Panel
    - Local HTML dashboard (accessible at 192.168.4.1)
    - Sensor status display
    - Buzzer mute/test controls
    - Real-time updates

  • Backend Synchronization
    - Sends sensor data to FastAPI backend every 5 seconds
    - POST to /api/v1/sensors/data
    - Payload: {fire, pir, gas, water_level}

API ENDPOINTS (ESP32)
  • GET /api/sensors
    - Returns current sensor state
    - CORS enabled
    - Response: {ir, flame, gas, water, mq2_rating, buzzer, muted, raw_water}

  • POST /api/buzzer/toggle_mute
    - Toggles buzzer mute state

  • POST /api/buzzer/test
    - Plays test alarm (6 dual-tone pulses)

  • GET /
    - Serves local control panel HTML

INTEGRATION & COMMUNICATION
================================================================================

DATA FLOW ARCHITECTURE
  
  1. SENSOR LAYER (ESP32)
     └─ Reads hardware sensors → 10ms sampling
  
  2. ESP32 LOCAL API
     └─ /api/sensors endpoint → JSON response
  
  3. FRONTEND (React)
     ├─ Primary: Direct fetch from 192.168.4.1/api/sensors (10ms)
     ├─ Secondary: Backend proxy /api/v1/sensors/esp32/live
     └─ Tertiary: Stored /api/v1/sensors/status
  
  4. BACKEND (FastAPI)
     ├─ Proxy endpoint: /api/v1/sensors/esp32/live
     │  └─ Fetches from ESP32 via httpx.AsyncClient
     ├─ Storage endpoint: /api/v1/sensors/data (POST from ESP32)
     └─ Status endpoint: /api/v1/sensors/status

NETWORK CONNECTIVITY
  • Direct Connection (Primary)
    Protocol: HTTP
    Address: 192.168.4.1:80 (ESP32 AP)
    Latency: ~5-50ms
    CORS: Enabled
    Use Case: Real-time sensor monitoring

  • Backend Proxy
    Protocol: HTTP
    Address: localhost:8000 (FastAPI)
    Latency: ~1-5ms (local)
    CORS: Enabled
    Use Case: CORS bypass, data aggregation

  • Backend to ESP32
    Protocol: HTTP
    Client: httpx.AsyncClient
    Purpose: Fetch live data, transform, cache

DATA SYNCHRONIZATION
  • ESP32 → Backend: Every 5 seconds (POST)
  • Frontend → ESP32: Every 10ms (GET)
  • Frontend → Backend Proxy: 10ms fallback
  • Backend Cache: In-memory storage of last known state

CORS POLICY
  Frontend: http://localhost:5173
  Backend: http://localhost:8000
  ESP32: http://192.168.4.1
  
  Allowed Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS
  Allowed Headers: Authorization, Content-Type
  Credentials: Enabled
